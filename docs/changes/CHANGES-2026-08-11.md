# Property Lookup — changes, 11 August 2026

Outcome of a full code review of both lookup pages. Ten findings, all closed across six commits on
`fix/address-suggestion-truthfulness-and-cancellation`. Every fix was written test-first and verified
against the live ArcGIS services as well as the mocked suite.

Test suite: **10 unit / 4 Python / 28 browser** before → **23 / 4 / 47** after.

Two findings were resident-facing defects that returned wrong or incomplete answers. The rest were
divergence, exposure and contract gaps that let a future change break something silently. They are
ordered by consequence, not by effort.

> **Scope note.** This is a historical change report, like `CHANGES-2026-08-06.md`. Current behavior
> is documented in `README.md`, `CODE.md`, `USAGE.md` and `DATA-SOURCES.md`. Where this report and
> those files disagree, those files are correct.

---

## 1. Address lists were announced as complete when the service had capped them

**The problem.** Every search tier passes `resultRecordCount: address.max` (10). Real streets exceed
that, and the live region announced a bare count, so ten of forty-nine read as the whole answer.

| Typed | Actual matches | Shown | Announced |
|:--|--:|--:|:--|
| `Santa Rosa` | 49 | 10 | "10 address matches." |
| `3300` | 1,268 | 10 | "10 address matches." |
| `Millcreek` | 264 | 10 | "10 address matches." |
| `Wasatch` | 180 | 10 | "10 address matches." |

A resident whose address was not among the ten had no signal that more existed. `orderByFields` is
`FullAdd`, so the ten that survive are an arbitrary alphabetical slice — the first ten for
`Santa Rosa` began at 3261 E, so anyone further down the street received ten wrong addresses and a
message implying there were no others. This is the primary navigation path of a page whose stated
purpose is to work without a map, a mouse, or vision, and it failed silently.

**The fix.** ArcGIS already reports the cap in `exceededTransferLimit`, and the response field was
being discarded. `findAddresses()` now returns it and the live region says the list is partial and
what to add:

> Showing the first 10 matches. More addresses match than are listed. Use arrow keys to review them.
> Add the direction or street type to narrow the list, for example "3300 E Santa Rosa Ave".

Read from the flag, **not** inferred from the row count: address points without a parcel ID are
filtered out after the response arrives, so a capped result can arrive shorter than the cap and a
count-based check would call it complete.

Submitting free text no longer auto-loads a lone match when the service reported a cap. One row out
of a truncated result is not a unique match.

**Two things deliberately not done.** `AddNum` is `esriFieldTypeString`, so there is no numeric
server-side ordering available — sorting by house number was investigated and withdrawn. And
`address.max` stays at 10: raising it is a UX trade-off (a longer list to arrow through) rather than
a fix, and belongs to whoever owns the resident experience.

## 2. The licensing page could screen the previous parcel, or hang

**The problem.** `business-licensing.html` claimed its cancellation ticket *inside* the debounced
search rather than in the input event that scheduled it. Anything the user did during the 250 ms
window was therefore answered with stale state or discarded without a word.

- **Wrong parcel.** `chosen` was cleared inside `suggest()`, 250 ms after typing. Editing the field
  after choosing an address and submitting inside that window screened the **previously selected
  parcel** while the input displayed the newly typed address.
- **Silent hang.** A suggestion still queued when an address was chosen took its own ticket when it
  fired and aborted the in-flight lookup. Because the abort is classified as cancellation it was
  discarded without an error, leaving the page on "Checking …" indefinitely with the suggestion list
  reopened.

The hang reached **keyboard selection only**, and that is the interesting part. A pointer click was
protected by accident: `pick()` empties the listbox, so the click reaches the document handler with a
detached target, `closest(".combo")` returns `null`, and the dismissal handler cleared the pending
timer as a side effect. Choosing with Enter fires no click and had no such accident to rely on — so
the exposed path was the keyboard one this page exists for.

**The fix.** Adopt `index.html`'s task ownership, which was already correct:

> **The event that starts a user action claims the ticket. Work the action merely schedules never
> does.**

The input event now clears the stored selection and takes the ticket synchronously; the debounced
search inherits it. Choosing, submitting, clearing and dismissing all cancel the pending timer.
`activeKind` replaced a bespoke `suggestionMine` counter so a dismissal can invalidate a pending
search without disturbing a lookup.

## 3. One request layer, held byte-identical

**The problem.** The licensing page carried its own copy of the REST helpers, and the copies had
drifted into different behavior for the same failures:

| | `index.html` | `business-licensing.html` (before) |
|:--|:--|:--|
| Retry policy | `network`, `busy`, `server`, `timeout` only | **every** error, including HTTP 400 and rejected queries |
| Already-superseded request | not sent | sent, answered, then discarded |
| Failure reporting | classified `kind` → `explain()` | one collapsed string per call site |

Retrying a rejected query cannot change its answer. It doubled the worst case to two full 12-second
timeouts and added load to a service that may already have been refusing work.

**The fix.** `index.html`'s layer copied in verbatim between markers, with a unit test comparing the
two regions **byte for byte**. The bytes were extracted and spliced by script rather than retyped, so
identity is guaranteed by construction.

Two identical copies is not the end state, and the duplication is deliberate. ADR-0001 replaces both
inline scripts with shared modules; identical copies extract mechanically and the diff proves parity,
while divergent copies force an undocumented merge decision per difference, during a migration, with
no tests on the differences. Converging them is the step that makes the extraction safe.

The block reads `org`, `request.*` and `contact.phone` from whichever `CFG` it is embedded in, so the
licensing page gained a `contact` block carrying Business Licensing's `801-214-2759`.

Verified live: HTTP 400 → classified `http`, attempted **once**. HTTP 503 → classified `server`,
attempted **twice**.

## 4. The site was publishing the entire repository

**The problem.** `publish = "."`. Confirmed against the live deployment before changing anything —
each of these returned HTTP 200 with its own content, not the app:

| Path | Served |
|:--|--:|
| `/CODE.md` | 11,830 bytes |
| `/docs/ideas/modular-municipal-geospatial-application.md` | 17,013 bytes |
| `/scripts/check-services.mjs` | 13,774 bytes |
| `/package.json`, `/tests/unit.test.mjs`, and the rest of the tree | — |

The catch-all rewrite did not mask them; Netlify serves real files first. No credentials are involved
— there are none in this repository — but the migration proposal, the code walkthrough, the
data-source review register with its replacement candidates, and the service-contract script with its
known test parcel IDs are internal engineering material that was published by accident rather than by
decision.

**The fix.** The deployed site moved to `public/` and Netlify publishes that directory. This is an
**allowlist**: a file is served because it was added to `public/`, not because it was committed. A
deny list of paths would need extending every time a document is added, and the default for the
forgotten case would be "public".

`_headers` moved with the site, because Netlify only honours it from inside the publish directory.
Leaving it behind would silently drop the CSP and every other security header, so the unit test
asserts its presence there specifically.

Two guards, because the local and deployed shapes can disagree:

1. A unit test reads the publish directory out of `netlify.toml`, requires the four files the site
   needs, and fails if anything under `docs/`, `scripts/`, `tests/`, `.github/` or the root documents
   appears inside it.
2. `check-deployment.mjs` probes ten repository paths against the live site. Status codes cannot
   express this, because the catch-all rewrite answers unmatched paths with the app at HTTP 200 — so
   it compares bodies. If a repository file is being published, its own content comes back instead of
   the app.

Local runs serve `public/` too (`http.server --directory public`), so a test cannot reach a file the
deployed site does not serve.

The catch-all rewrite and its soft 404 are unchanged and remain deliberate. Scoping the publish
directory is what stops it masking real files.

## 5. Parcel fields the page displays are now verified

**The problem.** `npm run check:services` verifies whatever `CFG` declares. `own_name`, `care_of` and
`slc_link` were read out of the parcel record by name in the rendering code, so they were invisible to
it — the only displayed fields nothing checked. A rename at the County would not have produced an
error. The owner-of-record block and the Assessor valuation link would have stopped appearing, in
every result, with a green test suite and a passing service contract.

**The fix.** Named in `CFG` as `ownerField`, `careOfField` and `assessorLinkField`, read through `CFG`
in `draw()`, and added to the parcel spec in `check-services.mjs`. Three unit tests hold that shape:
the declarations exist, the rendering code no longer reads those fields by literal name below the
configuration marker, and the contract check derives them from `CFG` rather than repeating the names.

`prop_location` is also read by name but was already covered, because it appears in `PARCEL_FACTS` and
therefore in the derived contract.

**The same gap from the other side.** `ownerPair()` splits the Assessor's semicolon-separated owner
string and expands tenancy codes — `(JT)` → "joint tenants" — so a screen reader does not read one
run-on line. Nothing asserted any of it. Three browser tests added: multiple owners become a list with
codes expanded, a single owner is labelled in the singular with its care-of line, and a record missing
all three fields still renders the rest of the parcel record.

Verified live: all three fields present on the parcel layer, the sample record carries the documented
semicolon-and-tenancy-code format, and `care_of` is whitespace-only there — which `decode()` already
treats as absent.

## 6. Status glyphs were being read aloud

`● Yes` shared one text node with its word on the licensing page, so a screen reader announced "black
circle Yes". The glyph moved into its own `aria-hidden` element, matching `index.html`, with the
`.flag .g` rule added for consistent rendering.

axe does not detect this, which is why it has an explicit test rather than relying on the existing
accessibility scan. Status remains glyph **and** word **and** colour (1.4.1).

## 7. Transport security is declared here, not left to the host

`check-deployment.mjs` asserted HSTS, and Netlify was supplying it from platform defaults — so the
gate depended on hosting behavior with no source in the repository. Move the site or the account and
it fails for a reason nobody can look up.

`public/_headers` now declares the value already being served, so this changes where the header comes
from and not what is served. The gate asserts the directives rather than the presence of `max-age=`,
because a shortened window or a dropped `includeSubDomains` is a downgrade worth failing on.

Recorded in `_headers` because it is easy to get wrong: `includeSubDomains` binds subdomains of the
host that sends it. From a subdomain such as `parcel.millcreekut.gov` that is only that subdomain's own
children. Serving this file from the `millcreekut.gov` **apex** would force HTTPS on every City
subdomain, which is a decision for whoever owns the domain. `preload` requires a submission to
hstspreload.org to mean anything; sending the token enrols nothing by itself.

## 8. Typed SQL wildcards no longer change the search

`esc()` doubled single quotes but left `%` and `_` untouched in `LIKE` clauses, so a typed wildcard
silently changed the search rather than being searched for.

| Typed | Before | After |
|:--|--:|--:|
| `330_ E` | **17 matches** — `_` acted as a single-character wildcard | 0 |
| `100% Main` | wildcard match | 0 |
| `O'Brien` | 0 | 0, no error |

`likeOperand()` escapes `%`, `_` and backslashes, and every tier now carries `ESCAPE '\'`. The service
was probed first to confirm it accepts the clause and that escaped wildcards match literally, before
anything depended on it.

The two helpers are deliberately not interchangeable, and a unit test says so: escaping wildcards in an
**equality** operand would be the opposite mistake, inserting backslashes into a literal value.

This is a behavior change, not purely a fix. `330_ E` previously returned 17 rows by coincidence and now
returns none, with the existing "try just the house number and street name" guidance. A wildcard match
is not something the resident asked for.

## 9. Smaller corrections

- **`NaN KB`.** `Math.round(f.size/1024)` rendered "NaN KB" when a service omitted `size`. The format
  is now stated alone in that case; an unknown size is better left unsaid.
- **CI provisions Python.** `npm test` runs `python -m unittest` and Playwright's `webServer` is
  `python -m http.server`, so the suite depends on that interpreter being on `PATH` under that exact
  name — previously left to whichever alias the runner image happens to ship.
  `actions/setup-python@v5` now provides it, and a unit test asserts the workflow keeps doing so.
- **`reuseExistingServer`.** Was unconditionally `true`; in CI an unexpected listener on port 4173
  could silently have become the thing under test. Now `!process.env.CI`.

## 10. Testability changed to make the rest provable

The 250 ms suggestion debounce was a literal in both pages. As a literal it made the cancellation
races untestable: on a slow run the timer fires, the assertion passes, and nothing was actually
exercised. It is now `CFG.request.suggestDebounceMs`, so a test can hold the window open on purpose.

This was not incidental. **Three of the reproduction tests written for §2 passed against the buggy
code** before that change, because Playwright's click latency exceeded the debounce and the suggestion
fired *before* the superseding action instead of after. They were rewritten to dispatch the input event
and the superseding action inside a single `page.evaluate`, so ordering is fixed by JavaScript rather
than by how fast the run happens to be.

A fourth test was wrong in a more dangerous way: it asserted only that a superseded request produced
`AbortError`, which reads as passing even when the request was sent and answered, because the name is
derived from `signal.aborted` in the `catch`. It now counts the round trip and asserts zero.

`index.html` already owned its ticket correctly and its behavior is unchanged, but the same invariants
are now pinned there by characterization tests — the ones that failed on the licensing page before it
was restructured — so the extraction into shared modules cannot quietly reintroduce the defect.

## Verification

- `npm test` — 23 unit, 4 Python, 47 browser/axe. Green.
- `npm run check:services` — full live contract run passes: every configured layer and field, the
  known-address and known-parcel lookups, both FEMA/Millcreek flood congruence checks, the historic
  designation distinction, short-term-rental buffer geometry, and public-web-map parity across 21
  adopted layers.
- Both pages driven against the live services in a browser: capped and uncapped searches, the
  wrong-parcel and stuck-lookup scenarios, retry classification, `explain()` offering the correct
  contact number per page, and status flags exposing their word with the glyph hidden. No console
  errors.
- Both HTML files remain pure LF (0 CRLF), so `check-deployment.mjs`'s byte-exact comparison holds.

**Still outstanding, unchanged from 6 August:** the manual keyboard-only pass and the NVDA pass.
Automated checks catch roughly 25–40% of WCAG issues, so no public conformance claim should be made
until those are done.

## Two decisions left open

1. **`CFG.release.version` is still `2026.08.09`.** The footer and the copied output both print it, so
   it currently tells residents this is the 9 August build across six commits of behavior change.
   Bumping it is a release act, which ADR-0001 reserves for designated human approval.
2. **`address.max` is still 10.** Now honestly disclosed. Raising it would surface more addresses per
   search at the cost of a longer list to arrow through — a resident-experience call, not a defect.

## Notes for the next round

1. **The two pages are converged, not deduplicated.** The shared request layer is held identical by a
   unit test so that ADR-0001's extraction is mechanical. `el()`, `flagPair()` and the address parser
   are the next candidates and are still divergent — the licensing page has no `el()` at all.
2. **`check-services.mjs` verifies what `CFG` declares, and only that.** Any field the pages display
   must be named in `CFG` before it is displayed, or it is unverifiable by construction. §5 is what
   that failure looks like: not an error, just an answer that quietly stops appearing.
3. **`exceededTransferLimit` may not be the only response field being discarded.** It was present in
   every address response from the beginning. A sweep for others the services already report would be
   cheap.
4. **A capped list is disclosed but not paginated.** The address service reports
   `supportsPagination: true`. If residents still report not finding their address on a long street,
   `resultOffset` with a "show more" control is the next step — but for a screen-reader user, guidance
   to narrow the search is likely better than a longer list.
5. **The soft 404 is deliberate and still there.** Every unknown path returns HTTP 200 with the app.
   That is documented in `netlify.toml` as intentional so a mistyped deep link still reaches a working
   form. Worth revisiting only if it starts mattering for search indexing.
