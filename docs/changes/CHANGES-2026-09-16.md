## 1. The worked example was a private residence (PR #48 follow-on)

**Found.** While reviewing the morning's documentation commits. Section 9 of
[CHANGES-2026-09-15.md](CHANGES-2026-09-15.md) had already been moved off a privately owned
commercial parcel that morning — but the same review found the app's *own* front-page example was
worse: `3300 E Santa Rosa Ave` / `16264570030000` is a private residence whose owners of record are
two named individuals. Confirmed against the live parcel service, not assumed.

**How wide it was.** The form hint on **both public pages** — the first thing a resident or a
search-engine crawler sees — plus the "no match" guidance, `README.md`, `USAGE.md`'s address-variant
list, the manual screen-reader script, `scripts/check-services.mjs`, and every mocked test fixture.
The test fixtures already used invented owner names (`ALEX EXAMPLE`), so only the address and parcel
number were real.

**Replaced** with `1344 E Chambers Ave` / `16283040280000` — owner of record `MILLCREEK`, the same
city parcel §9 had moved to. Verified against the address-points layer that the address resolves to
that parcel, so the example works when a resident types it.

**Two examples deliberately did not become Chambers.** The address-parser comments needed a two-word
street name *with* a street type, which Chambers (one word) cannot show; they use a constructed
`1200 E MOUNTAIN VIEW DR`, where the street exists but that house number does not, so no real home
illustrates a code comment. `CODE.md`'s "a street such as Santa Rosa has 49 matching points" stays:
it names a street rather than a property or an owner, and it is a real measurement about overflow
behaviour that Chambers, with 5 points, cannot stand in for.

Dated changelogs under `docs/changes/` were left as written. They record what was true on the day.

**Verified:** 90/90 unit (at the time), 4/4 Python, 129/129 browser through system Chrome, and
57/57 live service contracts against the new address.

## 2. An accessibility testing workbook, and three broken script steps

`docs/manual-screen-reader-test.md` assumed a reader who already knew what NVDA was and what
sign-off meant. [`accessibility-testing-workbook.md`](../accessibility-testing-workbook.md) is the
app-independent half: NVDA install, the eight keys that matter, VoiceOver equivalents for testing
from a Mac, how to write a finding that can be acted on, and what sign-off commits the city to. It
ends with how to write a script for another application — including the rule that test data must be
publicly owned, which is the lesson of §1 above.

The parcel change had broken three steps in the script itself:

- **B5** still said `3300 East Santa`, which now matches nothing. Now `1344 East Cham`.
- **C3**'s spoken digits still read `1 6 2 6 4…`. Now `1 6 2 8 3…`.
- **C5** expected "a list of 2 items, each ending *joint tenants*". The city parcel has a single
  owner, `MILLCREEK`, and no joint tenancy, so the step could not be run as written. It now checks
  the single-owner case on the test parcel and directs the tester to any two-owner parcel for the
  "jay tee" expansion, which is what the step exists to catch.

Checked against the live service that the other parcel-dependent steps still run: `16283040280000`
has one recorded plat (`MILLCREEK CITY CENTER OPEN SPACE SOUTH`, `2023P-047`), so C11 is intact.

**The results table is still unsigned.** A full NVDA pass is scheduled for the week of 2026-09-21.

## 3. Netlify retired (ADR-0005)

Three reviewed changes in the repository, then one irreversible dashboard action.

**What running two hosts cost.** `scripts/deployment-content.mjs` tolerated three transformations
Netlify applied to served bytes — two Pretty URLs link rewrites, the deploy-preview drawer, and from
26 August a marketing comment and two meta tags carrying UTM tracking and the site id. Two files
declared the same six response headers with nothing at runtime to notice them drifting apart. And
`check:deployment` points at one URL, so whichever host it was not pointed at went unverified — in
practice, always Netlify.

**What changed.**

- All three content allowances are gone; the gate now requires exact bytes. The unit tests that
  pinned them are replaced by tests asserting each retired transformation must now **fail**.
- `netlify.toml` and `public/_headers` are deleted, with the cross-host drift test.
  `public/staticwebapp.config.json` is the single source of headers, routes and cache rules, and an
  Azure-only test asserts what the drift test used to guarantee.
- Two tests were reading `netlify.toml` for things it was never the real source of. The publish
  allowlist now reads `outDir` from `vite.config.mjs` and the build script from `package.json`.
- `_headers` carried reasoning in comments that JSON cannot hold — why `'unsafe-inline'` is accepted
  for both `script-src` and `style-src`, and the warning that HSTS `includeSubDomains` sent from
  `lookup.gis.millcreekut.gov` reaches only that name's children, not `gis.millcreekut.gov` and not
  the apex. That moved to `CODE.md` section 1 rather than being lost with the file.

**Proved, not assumed.** The deployed commit `297e8667` was rebuilt with the stricter gate and run
against `https://lookup.gis.millcreekut.gov/`: both pages byte-exact, 24/24 repository paths
unpublished, every declared header present, and **no tolerated transformation on any page**. Azure
serves the artifact verbatim, so removing the allowances costs nothing.

**The site itself.** Unlinked from GitHub, then deleted, then the GitHub App's access to this
repository removed. `parcel-lookup-millcreek.netlify.app` answered HTTP 200 that morning and answers
**HTTP 404** now; no Netlify check run or commit status reaches this repository. The app stays
installed on the account because two other Netlify sites are still in the wider retirement plan, so
its repository access was narrowed rather than revoked wholesale.

**Ordering, and why it was that way.** Every repository change is reversible with `git revert`; the
deletion is not. So the repository stopped configuring and verifying Netlify first, the site was
confirmed unnecessary, and only then was it deleted. Unlinking before merging mattered for a
specific reason: the site was still auto-building from `main` — byte-identical to the current build
apart from the injection — so merging while connected would have published a copy with no security
headers, `_headers` no longer being in the repository to supply them.

**Accepted deliberately:** one host is one point of failure. Rollback never depended on Netlify being
live — it depends on a known-good artifact being promotable, which it still is — but the ability to
serve from a second provider during an Azure outage is genuinely gone.
